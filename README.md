# AES-256 Pipelined Core in Verilog

A fully pipelined AES-256 encryption core written in plain Verilog, plus four
architecture variants built from the same verified round blocks. The design
accepts one new 128-bit block per clock once the pipeline is full
(initiation interval = 1) and expands the 256-bit key on the fly.

## Verification status (read this first)

- **Behavioural simulation: verified.** The self-checking testbench streams
  five known-answer vectors back to back (the FIPS 197 AES-256 example and
  four NIST SP 800-38A vectors) and every variant in this repo passes it
  unmodified under Icarus Verilog.
- **Synthesis: measured for resource use only.** Post-synthesis utilisation
  and vectorless power were measured in Vivado for the Xilinx Artix-7
  XC7A100T-1CSG324C (Digilent Arty A7-100T). No timing report was run, so
  **fmax is not claimed anywhere in this repo**; latency and throughput
  figures are in clock cycles, or computed at the 100 MHz constraint clock
  where stated.
- **Not done:** implementation (place and route), programming a physical
  board, and decryption. The core is encryption only.

## Architecture

| Block | File | Role |
|---|---|---|
| S-box | `rtl/aes_sbox.v` | Byte substitution table |
| SubBytes | `rtl/aes_sub_bytes.v` | S-box applied to all 16 state bytes |
| ShiftRows | `rtl/aes_shift_rows.v` | Row rotation of the state |
| MixColumns | `rtl/aes_mix_columns.v` | GF(2^8) column mixing |
| AddRoundKey | `rtl/aes_add_round_key.v` | XOR of round key into the state |
| Round | `rtl/aes_round.v` | One full AES round from the blocks above |
| Key schedule | `rtl/aes256_key_schedule.v` | On-the-fly expansion, ready in 13 clocks |
| Top level | `rtl/aes256_pipeline.v` | 14-stage pipeline, one round per stage |

## Variants

All five designs pass the same unmodified testbench.

| Variant | Folder | Idea | Latency (cycles) |
|---|---|---|---|
| Pipelined (baseline) | `rtl/`, `tb/`, `sim/` | One round per pipeline stage | 14 |
| Sub-pipelined | `variants/sp/` | Each round split into two half-stages | 28 |
| Sub-pipelined + composite-field S-box | `variants/spcf/` | Sub-pipelined, with the S-box rebuilt as GF(2^4) composite-field logic instead of a table | 28 |
| Two rounds per stage | `variants/2r/` | Two rounds of logic between registers | 7 |
| Iterative | `variants/iter/` | One round unit reused under a controller | 14 (II = 15) |

The composite-field S-box in `variants/spcf/` was generated by
`variants/spcf/sim/gen_sbox_cf.py` and matches the table S-box on all 256
inputs.

## Running the simulation

Requires Icarus Verilog. For the baseline design:

```sh
cd sim
iverilog -o aes256_sim -f files.f ../tb/tb_aes256_pipeline.v
vvp aes256_sim
```

Each variant folder has the same layout (`rtl/`, `tb/`, `sim/files.f`) and
runs the same way. The testbench prints a PASS line per vector and a summary
at the end.
